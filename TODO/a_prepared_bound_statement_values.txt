CURRENT STATE:
SeaStarBoundStatement stores raw Java values in Object[] and exposes them via getBoundValues().
SeaStarCqlRequestHandler already reads getBoundValues() directly, so simple bind() paths work,
but the driver-facing GettableByIndex/SettableByIndex contract (getValues, getBytesUnsafe,
size, getType, firstIndexOf) is unimplemented. PreparedStatement exposes no variable or
result-set ColumnDefinitions, so any client that inspects bind-marker metadata fails.

WHAT REAL CASSANDRA/DRIVER DOES:
- PreparedStatement.getVariableDefinitions() returns ColumnDefinitions describing each bind
  marker (name, keyspace, table, DataType), derived from parsing the statement against schema.
- getResultSetDefinitions() returns the columns a SELECT will yield (empty for writes).
- BoundStatement is GettableByIndex/SettableByIndex over ByteBuffers, encoding values via the
  CodecRegistry + ProtocolVersion.

IMPLEMENTATION PLAN:
1. Build ColumnDefinitions for bind markers when preparing. The statement is already parsed by
   Cassandra's QueryProcessor in SeaStarCqlRequestHandler; extract bind-marker names/types from
   the parse tree (Reflections into the Raw statement) resolved against the target table columns.
   Store them on SeaStarPreparedStatement so getVariableDefinitions() returns them.
2. getResultSetDefinitions(): for SELECT, build ColumnDefinitions from the selected columns; for
   writes return empty ColumnDefinitions. Wire setResultMetadata to store the pair.
3. Implement SeaStarBoundStatement as a proper SettableByIndex/GettableByIndex:
   - size() = number of variable definitions
   - getType(i) = variable definition i's DataType
   - firstIndexOf(name/id) = index lookup in variable definitions
   - getBytesUnsafe(i)/setBytesUnsafe(i): encode/decode via context.getCodecRegistry() and
     context.getProtocolVersion() (see the commented ValuesHelper.encodeValues reference).
   - getValues(): return encoded ByteBuffers for all bind values.
4. boundStatementBuilder(): return a BoundStatementBuilder over this prepared statement.
5. Fidelity: binding the wrong number/type of values should throw the same driver exception a
   live cluster throws (IllegalArgumentException / InvalidQueryException).

DEPENDENCIES: benefits from concept (b) complex column types for non-native bind markers, but
native-type support can land first.
