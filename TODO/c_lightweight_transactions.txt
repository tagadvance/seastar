CONCEPT: Lightweight transactions (LWT) - IF / IF NOT EXISTS / IF EXISTS and [applied] result sets
PRIORITY: 3 (common CQL feature; currently throws or silently ignores conditions)

- UpdateHandler.java:89     conditional UPDATE (IF <condition>) throws UnsupportedOperationException (// TODO)
- UpdateHandler.java:122    upsert when PK restricted by IN; IF EXISTS should report [applied] (// TODO)

CURRENT STATE:
- INSERT ... IF NOT EXISTS applies the row conditionally but returns a normal (empty) result set,
  not the [applied] boolean column a real LWT returns.
- UPDATE/DELETE with an IF <condition> clause throw UnsupportedOperationException.
- UPDATE IF EXISTS partially handled (skips upsert) but does not report [applied].

WHAT REAL CASSANDRA DOES:
LWT statements return a one-row result set whose first column is boolean "[applied]". When the
condition fails, [applied]=false and the row also contains the current values of the checked
columns. When it succeeds, [applied]=true.

IMPLEMENTATION PLAN:
1. Define a shared helper to build an "[applied]" AsyncResultSet: a single row with a boolean
   [applied] column, plus current column values on failure. Put it where the handlers can share
   it (e.g. a static in CqlHandler or a small util).
2. InsertHandler IF NOT EXISTS: return [applied]=true when the row was inserted, [applied]=false
   plus the existing row's columns when a row with the same PK already existed.
3. UpdateHandler / DeleteHandler: read the "conditions" list (already reflected) and evaluate
   each IF <col> <op> <value> against the matched row. Apply the mutation only if all conditions
   hold; return the [applied] result set either way. Remove the UnsupportedOperationException.
4. UpdateHandler IF EXISTS: return [applied]=true/false based on whether a matching row existed;
   only mutate when it did.
5. Handle PK-restricted-by-IN upsert path noted at UpdateHandler:122.
6. Fidelity: a condition on a non-existent column, or IF on a non-PK-complete WHERE, should throw
   the same InvalidQueryException a live cluster throws.

DEPENDENCIES: none blocking; independent of (a)/(b) though shares WHERE/assignment plumbing.
