CONCEPT: Secondary index support (CREATE INDEX + TableMetadata.getIndexes)
PRIORITY: 7 (less common; getIndexes currently throws)

SOURCE COMMENT (now removed):
- VolatileTable.java:131  getIndexes throws UnsupportedOperationException("Indexes are not
  supported in SeaStarTable") (// FIXME)

CURRENT STATE:
VolatileTable has no index storage; getIndexes() throws, so any client inspecting table metadata
for indexes fails, and CREATE INDEX is unhandled.

WHAT REAL CASSANDRA DOES:
CREATE INDEX defines a secondary index on a column, exposed via TableMetadata.getIndexes() as a
Map<CqlIdentifier, IndexMetadata>. Queries filtering on an indexed column are allowed without
ALLOW FILTERING.

IMPLEMENTATION PLAN:
1. Add an index map (ConcurrentHashMap<CqlIdentifier, IndexMetadata>) to VolatileTable; return it
   from getIndexes() (empty map, not an exception, when none exist).
2. Add a CreateIndexHandler (CqlHandler over Cassandra's CreateIndexStatement.Raw) that records
   the index on the target VolatileTable. Follow the add-cql-statement skill.
3. Register it in the CqlHandlerRegistry (see concept (k)).
4. Optionally let SelectHandler consult indexes to permit filtering on indexed columns; a first
   cut can just store metadata.
5. Fidelity: creating a duplicate index or indexing an unknown column throws the matching
   driver exception.

DEPENDENCIES: none blocking. Use the add-cql-statement skill for the new handler.
