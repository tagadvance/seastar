CURRENT STATE:
SeaStarCqlSessionBuilder builds an empty session; callers must issue CREATE statements or reach
into the Volatile model manually to set up schema.

GOAL:
Let a caller seed the session's keyspaces/tables/types from a schema source before first use, so
tests can point at an existing .cql file or classpath resource instead of hand-building schema.

IMPLEMENTATION PLAN:
1. Add builder methods to accept schema sources:
   - a CQL schema string / .cql file (parse and replay each statement through the handler pipeline)
   - a classpath resource path
   - a filesystem File / Path
2. On build(), read the source, split into statements, and execute each against the new session
   so the same CqlHandler code path populates the model (guarantees fidelity with runtime CREATE).
3. Surface parse/execution errors as the builder failing fast with a clear message.

DEPENDENCIES: relies on the CREATE handlers already implemented; complex-type schemas need
concept (b).
